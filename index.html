Useful recommendations before the data exists.

A new movie streaming platform has 20 real users. That isn't enough history to recommend anything well. A GAN learns how those users behave and writes thousands of synthetic users that look like them, so the recommender has something to learn from on day one.

Ananya Sharma, Rohan Verma, Meera Nair / Recommender Systems course project

Three ways a recommender starts cold

New user

No history, so the first screen is a guess.

Two clicks are enough: the model matches them against thousands of synthetic users with similar taste.

New item

No ratings, so collaborative filtering never shows it.

The generator writes interactions through item attributes, so a new release gets synthetic history from its genre.

New platform

A few users, nowhere near enough for a model to learn from.

20 real users become 20 + 5,000. Real rows stay in the training set; synthetic rows fill the gaps.

Train the GAN

The generator writes fake users. The discriminator tries to tell them from the 20 real ones. Each step, both get better, until the synthetic cloud covers the same tastes as the real users.

Generator

Takes 8 random numbers, turns them into a taste profile over categories, and scores every item through its attributes. That's why it can write history for new releases no real user has touched yet.

z ∈ ℝ⁸ → 32 ReLU → taste ∈ ℝ⁴ → σ(taste · attributes + bias)

vs

Discriminator

Looks at an interaction row and outputs the probability that it came from a real user. Its mistakes are the generator's training signal.

row ∈ {0,1}²⁰ → 32 LeakyReLU → σ → P(real)
